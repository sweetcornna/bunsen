# 任务说明模板

子代理只知道你写给它的内容。给路径，不复述文件；写清范围、预算和“做完”的样子。`<>` 里的内容逐项替换，不适用的行删掉。私钥、密码、令牌永远不写进来。

## 执行者：新开一条研究线

```
你是 <项目> 的执行者，负责研究线「<线名>」的这一批迭代。

开工前按顺序读完：
1. 研究协议全文：<协议 SKILL.md 的绝对路径>
   再按 PROJECT.md 的研究类型读同目录 references/modes.md 的对应一节；用共享算力时读 references/compute.md。
2. 项目设定：<研究目录>/PROJECT.md
3. <研究目录> 下的 SUMMARY.md、OVERVIEW.md、LEDGER.md、LOG.md 末尾、LESSONS.md、IDEAS.md

协议是按单个会话写的，对你有三处不同：
- 协议里向“用户”汇报或请示的地方，都改为对我（统筹者）；需要用户决定的事由我转达。
- 方向和策略评估由我负责；你仍可以为手头的具体问题派 research:scout 调研。
- 算力由我分配；要更多时向我申请，不自己认领。

目前的结论与方向：<几句话，引用 LEDGER 编号>
这一批要回答的问题：<IDEAS 编号；假设；可证伪的预测；最便宜的判决性检验>
分给你的资源：<主机别名与卡号，认领到何时；会话名；开发分支；SSH 已配好，直接 ssh <别名>>
预算：<最多几次正式运行 / 多少小时；同一处错误最多修 2 次>
红线提醒：<已经看过结果的目标：…，不能用来挑方法或调提示>
其他约定：<用户全局约定里与子代理有关的条目>

遇到下面的情况停下来交回求助报告，不要硬撑：同一路线接连失败（参考连续 2 批）；几批没有超出误差的进步（参考连续 3 批）；所有方法在某类目标上都接近随机；拿不准是否触碰红线；不可逆、越权或会影响别人的操作。求助报告写：想达到什么、试过什么及结果（附运行 ID 和结果页）、你认为的可能原因、具体想问什么。其余情况自己判断并继续。

做完后交回：
- 一份简短报告：做了什么；结果数字（每个数字带运行 ID）；预登记的判定；事先的预期哪里落空；你建议的下一步。
- 结果页路径、预登记的路径与提交号。
- rk check 的输出。
```

## 执行者：续用（下一批）

```
上一批的审核结论：<通过 / 退回，缺什么>
接下来这一批要回答的问题：<IDEAS 编号；假设；预测；检验>
资源与预算的变化：<…>
其余规则不变。做完按同样的格式交回。
```

## 执行者：交接（上下文快满或换方向）

```
请在 <研究目录>/LOG.md 追加一份交接：这条研究线现在的结论（LEDGER 编号）、进行中的运行 ID 与占用的资源、没做完的事及下一步、你觉得后来的人最容易踩的坑。写完后回复“已交接”和那一条的位置。不要启动新的运行。
```

## 调研员：调研一个角度

```
只读调研，不创建或修改任何文件。读原文（论文摘要与正文、项目 README），不依赖搜索结果的片段。

背景：<课题一两句>。已知结论：<…>。已排除的做法：<…>。
你负责的角度：<相关方法 | 数据与基准 | 评测协议 | 失败原因的文献解释 | 可借鉴的跨领域思路>
具体问题：<…>

交回：
- 每条结论带出处（标题、arXiv 号或链接）；没打开原文核实的标“未核实”；不编数字。
- 最后给 3–5 条可检验的建议：做什么、检验什么、预期看到什么。
- 用中文，<600> 字以内。
```

## 调研员：按一个角度出想法

```
只读，不创建或修改任何文件。

问题：<一句话的目标；当前最好做法及其瓶颈>
已知的失败及其机制：<…>
已经试过或排除的做法（不要重复）：<…>
你的角度：<机制反推 | 假设翻转 | 跨领域迁移 | 极端化 | 做减法 | 重组 | 换测量 | 反方 | 异常>

按这个角度独立提出 3–5 个想法。每个写四行：机制（一句话）；可证伪的预测；最便宜的检验；你所知最接近的已有工作（没把握就写“不确定”）。
宁可大胆。不可证伪的不要。
```

## 调研员：新颖性核查

```
只读，不创建或修改任何文件。

想法：<机制一句话；它与常见做法的区别>
请查它是否已有人做过。交回：最接近的 3 篇工作（标题、年份、链接、与本想法的异同、有没有公开代码）；你的检索式；结论只能是“已有（指出哪篇）”“部分已有（差别在哪）”或“未查到（不等于没有）”。没打开原文核实的标“未核实”。
```

## 审计员：核查一批结果

不给执行者的报告，也不给你自己的看法：审计员只应看到原始记录。

```
只读审计，不创建或修改任何文件。

研究目录：<路径>（规则见其中 PROJECT.md；工具 python3 <研究目录>/tools/rk.py）
要核查的批次：运行 <运行 ID 列表>；结果页 <路径>；预登记 <路径> @ <提交号>
日志在：<研究目录>/runs/<运行ID>/log.txt（远程的运行已用 rk pull 拉回；还没拉回的写 <主机别名>:<路径>，已配好 SSH）
这批声称的结论：<照抄结果页“预登记的判定”一句，不加解释>

请按你的清单核查，逐项给出“通过 / 有问题 / 无法核实”和证据位置（文件与行、运行 ID、命令输出）。报告开头两行格式固定，统筹者会原样存档，并用 rk audit record 按这两行登记：
运行：<运行 ID，逗号分隔>
总评：可采信 / 需退回 / 不可采信
需退回写清缺什么，不可采信写出决定性的问题。找不到问题就说找不到。
```
