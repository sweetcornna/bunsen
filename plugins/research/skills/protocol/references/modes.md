# 各类研究里的八条不变量

按 `PROJECT.md` 的研究类型读对应一节。一个项目可以同时属于几类（例如先综述、再做实验），每一批按那一批的类型执行。“参考规范”是该领域通行的报告清单，写结果页和最终报告时对照；细节以规范原文为准。

## 目录
1. 计算 / 机器学习实验
2. 既有数据的统计分析
3. 理论 / 数学 / 证明
4. 文献综述 / 证据综合
5. 仿真 / 建模
6. 工程 / 系统 / 基准构建
7. 需要人执行的实验（代理只设计与分析）
8. 定性 / 调查研究

---

## 1. 计算 / 机器学习实验

- **预登记**：数据划分、去重方式、指标与打分方向、对比方法及各自的调参预算、判定阈值、区间算法。写进分析脚本。
- **对照**：常数或多数类对照；最强的已有方法（只用有公开代码的）；消融。
- **筛选 → 确认**：源数据内部筛选（留一源、交叉验证），通过后在没看过的目标上评一次。
- **核验**：独立复跑关键运行；按泄漏清单逐项查（划分前做了预处理、重复样本跨划分、用了未来信息、目标信息进了特征、在测试集上调参或早停）。
- **记录**：代码与数据版本、种子、超参、全部运行（含失败）。
- **典型失败**：数据泄漏；在测试集上选模型；只报告最好的种子；削弱基线；固定墙钟预算的结果跨硬件比较。
- **参考规范**：ML 可复现性清单；Kapoor & Narayanan 的泄漏分类（arXiv:2207.07048）。

## 2. 既有数据的统计分析

- **预登记**：主假设与主结局、纳入与排除规则、模型设定、多重比较的处理；写明已经看过数据的哪些部分。
- **对照**：预登记的主设定；同时跑全部合理设定（多元宇宙 / 设定曲线）作稳健性对照。
- **筛选 → 确认**：先锁定一份留出数据不看；探索只在其余数据上做，确认在留出数据上做一次。
- **核验**：报告全部设定下效应的分布，不只报告显著的；另一人或另一个代理按预登记独立重算。
- **记录**：数据来源与版本、每一步排除的条数、试过的全部分析路径。
- **典型失败**：分叉路径；事后假设当事前假设；选择性报告；混淆因果与相关。
- **参考规范**：OSF 二次数据预注册模板；STROBE（观察性研究）；Simmons, Nelson & Simonsohn 2011。

## 3. 理论 / 数学 / 证明

- **预登记**：定理的精确陈述，包括全部假设与量词；什么算“证明了”；打算用的检验（特例、数值、形式化）。
- **对照**：已知结果与特例；极限情形；刻意寻找反例。
- **筛选 → 确认**：先在特例和数值上检验猜想（探索），再写完整证明（确认）。
- **核验**：把成文的证明交给一个只看得到证明文本的新代理逐步检查，至少两次独立检查都通过才记“已证实”；能形式化的用证明助手（如 Lean）；数值检查每个关键恒等式和常数。
- **记录**：完整证明文本（自足，不引用草稿）、所依赖的引理及其出处、检查记录。
- **典型失败**：悄悄加强假设或减弱结论；“显然”的一步其实不成立；凭记忆引用的定理条件不符；形式化的陈述与原意不一致。
- **提示**：纯数学难题可以配合官方的 math-proof 插件。

## 4. 文献综述 / 证据综合

- **预登记**：研究问题、检索的数据库与检索式、纳入与排除标准、要提取的字段、偏倚评估工具。在检索之前提交。
- **对照**：没有直接对照，以检索的完整性和可复现性代替：换一套检索式或数据库能否找回同一批核心文献。
- **筛选 → 确认**：先用一小批已知相关的文献校准检索式（探索），再按定稿的检索式正式检索一次（确认）。
- **核验**：两个独立的代理按同一标准分别筛选，不一致处逐条裁决；每条提取的事实回到原文核对，段落级引用。
- **记录**：每个库的检索式、检索日期、命中数；筛选流程图各步的数量；排除的理由。
- **典型失败**：只读摘要或搜索片段；引用不存在或内容不符的文献；纳入标准事后改；把综述里的转述当原始证据。
- **参考规范**：PRISMA 2020；PROSPERO 的协议登记要求。

## 5. 仿真 / 建模

- **预登记**：目的、数据生成机制、被估计的量、参加比较的方法、性能指标（ADEMP 五项）；重复次数与种子方案。
- **对照**：简单方法；有解析解或已知真值的情形。
- **筛选 → 确认**：小网格、少重复先看趋势（探索），再按预登记的全网格跑一次（确认）。
- **核验**：代码在已知解的情形下复现真值；报告 Monte Carlo 误差；对关键参数做灵敏度分析。
- **记录**：种子、参数网格、重复次数、未收敛或失败的重复数。
- **典型失败**：只挑对自己方法有利的场景；事后选性能指标；把仿真里的结论推到未验证的现实条件。
- **参考规范**：Morris, White & Crowther 2019（ADEMP）。

## 6. 工程 / 系统 / 基准构建

- **预登记**：任务定义、成功指标、测试集或负载的构成、全部对比方案及各自的调优预算。构建规则在抓取或构建之前写定。
- **对照**：强而简单的基线；逐项消融。
- **筛选 → 确认**：开发集上迭代，留出集或留出负载上评一次；多个数据集或环境上复查。
- **核验**：度量是否真的测到想测的东西（构念效度）；同等硬件与预算下比较；换一组种子或一天重测。
- **记录**：版本、硬件、配置、失败的运行、每次测量的原始数据。
- **典型失败**：对基准过拟合；比较对象的调优预算不对等；只在一种环境下测；基准本身有泄漏或标注错误。

## 7. 需要人执行的实验

代理负责设计、功效分析、分析脚本和结果解读；实验操作、伦理审批、采购由人完成。

- **预登记**：完整协议、样本量与功效计算、随机化与盲法方案、主要与次要终点、排除标准、分析脚本。在收集数据之前提交。
- **对照**：随机对照；安慰剂、溶剂或阴性对照；阳性对照。
- **筛选 → 确认**：预实验只用来估计方差和打磨流程（探索），正式实验按协议做一次（确认）。
- **核验**：分析脚本先在模拟数据上跑通再碰真实数据；按协议逐项对照实际执行，偏离逐条登记。
- **记录**：随机化序列、盲法执行情况、每一处偏离、失访与排除。
- **典型失败**：事后改终点；功效不足；不报告失访；把预实验数据并入正式分析。
- **代理的边界**：需要人做的步骤写进 `PROJECT.md` 的“需要人做的事”和 `SUMMARY.md` 的“需要你决定的事”，用 `rk run --manual` 登记后等待；数据没回来就写“未做”，绝不模拟或补造数据充数。等待期间可以先写好分析脚本并在模拟数据上验证。
- **参考规范**：Registered Reports 的两阶段流程；CONSORT 2010（临床试验）；ARRIVE 2.0（动物实验）。

## 8. 定性 / 调查研究

- **预登记**：研究问题、抽样方案、访谈提纲或问卷、编码本初稿、分析计划。
- **对照**：没有标准对照；主动寻找反面案例和不符合主题的材料。
- **筛选 → 确认**：先在少量材料上发展编码本（探索），定稿后再对全部材料编码（确认）。
- **核验**：两个独立的编码者对同一批材料编码并计算一致性；结论回到原始材料逐条找出处；三角互证。
- **记录**：原始材料或转写、编码本的修改史、每条结论对应的原文位置。
- **典型失败**：编码标准中途漂移；选择性引用；从少数案例过度概括。
- **参考规范**：COREQ。
