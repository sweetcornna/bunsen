# 交接一条研究线

用户的参数：

$ARGUMENTS

同一条研究线同一时刻只由一台机器推进。交接只搬项目和摘要，不搬对话：接手的机器拉取仓库、取得推进权，再用 `/research:resume` 从文件接着做。下文 `rk` 指 `python3 research/tools/rk.py`。

## 1. 弄清要交什么

- 参数里缺线名就执行 `rk line status`，只有一条本机持有的线时就交它，否则问用户交哪条。
- 目标机器代号是那台机器上 `rk id` 给出的代号。用户只给了主机别名时，执行 `ssh <别名> python3 <研究目录>/tools/rk.py id` 查。
- 跨机器交接需要两台机器都能连上的协调主机。`rk line config` 显示“未配置”时，按 `research:lab-access` 找到协调主机，执行 `rk line config --collab "ssh <协调主机别名> python3 <共享目录>/collab.py"`；目标机器上也要配一次（它在协调主机上就用 `python3 <共享目录>/collab.py`）。

## 2. 前置检查，逐项修好

```
rk handoff <线> --to <代号> [--remote <别名>:<研究目录>] --dry-run
```

它一次列出所有问题，每条带修复办法。常见的几条：

- **有没提交的改动**：确认都是这条线该留下的记录，提交（说明写“交接前提交”）。不是你的改动就问用户。
- **落后研究分支 / 同步没完成**（设了研究分支时）：`rk sync`；报冲突就照提示 `git merge` 研究分支、解决冲突并提交，再 `rk sync`。
- **落后上游 / 没有上游**（没设研究分支时）：`git pull`，或 `git push -u origin <分支>`；也可以 `rk sync --setup` 改为按研究分支汇合。
- **这条线还有运行没结束**：默认等它们结束（`rk wait`）。用户要马上交接时加 `--leave-runs`：运行留在本机跑完，交接摘要里会写明接手的机器怎样 `rk pull` 拉回记录。
- **占着的卡**：没有进程的认领现在释放；有进程的保留，并在交接说明里写清哪台主机哪张卡、预计何时结束。
- **目标机器连不上或代号不对**：照提示改。

直到 `--dry-run` 显示“前置检查通过”。

## 3. 写交接说明并交接

交接说明三到五句，写给接手的统筹者：这条线做到哪、正在等什么、下一步做什么、要注意什么（留下的运行、占着的卡、用户还没回答的问题）。数字带运行 ID。

```
rk handoff <线> --to <代号> --note "<交接说明>" [--remote <别名>:<研究目录>] [--leave-runs]
```

它依次：写交接摘要 `handoffs/<时间>-<线>-<本机>-<目标>.md`（交接说明加上 `state/<线>.md`、`LOG.md` 末尾、需要用户决定的事的原文），盖章并提交，推送（设了研究分支时经 `rk sync` 推上本机的 sync 分支和研究分支），在协调主机上把推进权交给目标机器。带 `--remote` 时还会在目标机器上 `rk sync --pull` 并取得推进权。中途失败（网络、协调主机）就原样重跑同一条命令，已完成的步骤会跳过。

交接之后本机不再写 `state/<线>.md`，钩子会拦下。执行者还在为这条线工作的，用 `SendMessage` 请它在安全点停下，在 `LOG.md` 写一句交接。

## 4. 收尾并告诉用户

- 本机不再持有任何研究线时，`rk loop off`。
- 告诉用户：交给了哪台机器、推进权编号、留下了什么（运行、卡）、接手的人要做什么：

```
python3 research/tools/rk.py sync --pull
python3 research/tools/rk.py line take <线>
/research:resume <线>
```

（`sync --pull` 在没设研究分支的仓库里等于 `git pull`；设了研究分支时 `line take` 自己会先同步。）

在跑的运行默认跑完，不要为了交接中止它们。
