# 发散与收敛

要的不是一个好主意，而是一组机制各不相同、都能被便宜地证伪的候选，然后把算力押在最有判决力的几个上。

## 何时做

- 新方向开始；
- 路线受阻（协议里的求助信号出现）；
- 轮到 `PROJECT.md` 的探索配额；
- 出现了意外结果：落空的预期是最值得追的线索。

想法池里还有没检验过的好候选时，先检验，不再发散。

## 第一步：把问题说清

写下来，后面每个角度都要用：

- 一句话的目标；当前最好的做法；它卡在哪。
- 已知的失败及其机制（`LEDGER.md`、`LESSONS.md`）。
- 当前做法默认成立的前提，列 5–10 条。
- 受阻时，先写 2–4 个互斥的“为什么不行”，并为每个解释想一个能把它和其他解释区分开的观察。如果现在还区分不了，第一批实验就该是诊断实验，而不是新方法。

## 第二步：发散

每个角度独立产出 3–5 个想法，互相不看：

| 角度 | 问自己 |
|---|---|
| 机制反推 | 失败要成立，需要哪些条件同时为真？逐个破坏 |
| 假设翻转 | 把默认前提逐条取反，会得到什么做法 |
| 跨领域迁移 | 别的领域里结构相同的问题是怎么解的 |
| 极端化 | 把一个量推到 0 或无穷（十倍数据、零标签、无限算力、单个样本），做法会退化成什么 |
| 做减法 | 最笨的可行做法是什么；现有方法里到底是哪个部件在起作用 |
| 重组 | 把账本里已证实的部件和教训表里的教训重新拼装 |
| 换测量 | 瓶颈会不会在评测或观测本身；有没有一个新的诊断量能直接区分几种解释 |
| 反方 | 苛刻的审稿人会说哪里平凡、已知或不可能；认真对待每一条 |
| 异常 | 记录里有哪些没被解释的现象 |

做法：

- 你自己先独立写一份，再看别人的。
- 并行派 `research:scout`，每个只给问题陈述、一个角度和已排除的做法（模板见统筹者手册的 references/briefs.md）。不给它们看彼此的输出：独立才有多样性。
- 每个想法写成四行：机制（一句话）；可证伪的预测；最便宜的检验；最接近的已有工作。
- 问题小的时候自己按角度逐个写就够了，不必派人。
- 这一步不评判。大胆的、看起来不靠谱的都留下。

## 第三步：收敛

1. **去重成簇**。同一机制的变体归为一簇。
2. **淘汰**并写明原因（留在想法池里，不删）：不可证伪的；检验成本超出预算的；触碰红线的（例如要靠看过结果的目标来挑）；已被账本里否定的陈述排除的。
3. **新颖性核查**。对每簇的代表派调研员查最接近的已有工作，必须给出具体文献。已有且有公开代码的，改作基线；“未查到”不等于没有，照实记。
4. **成对比较**。两两问：哪一个的检验更能改变我们下一步的决定，而且更便宜？记下胜负理由。不给单个想法打绝对分。候选不多时全部两两比；多了就比几轮，每轮让战绩相近的对上。
5. **比较时看什么**：判决力（结果无论正反都会改变决定吗）；成立的可能性；成本；成立后影响有多大；与主线的独立性。
6. **组合**。选 1–2 个主线候选加 1 个探索位，跨簇选，不在一簇里挑三个。

## 第四步：落到实验

- 每个入选的想法写出可证伪的预测和判定规则，走预登记 → 冒烟 → 筛选。
- 能同时区分几个假设的实验排最前。
- **把一条线上的尝试当成树**：节点是一个具体变体和它的验证分数；下一步从验证分数最好的节点扩展，不从最后一次尝试扩展；每个节点有调试上限；一棵子树连续几次扩展都没有超出误差的提升就搁置，换一簇。
- **固定预算的快速筛选**（适用时）：每次尝试用同样的小预算、同一个验证指标、事先写好的保留或丢弃规则，写进一份预登记后可以连续试多个变体。只在源数据上做；结果只用来决定谁进入正式筛选。
- 发散可以天马行空，选择只能用源数据。一个想法如果是受目标上的结果启发的，在 `IDEAS.md` 备注里写明，它的确认必须换一个没看过的目标。

## 登记

- 每个想法在 `IDEAS.md` 占一行，包括被淘汰的。
- 在 `LOG.md` 记一条：这次发散的原因、用了哪些角度、产出多少、入选哪些、理由。
