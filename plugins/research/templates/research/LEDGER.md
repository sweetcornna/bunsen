# 结论账本（只追加）

项目依赖的每条结论各占一行。状态只有四种：已证实 / 已否定 / 未决 / 撤回。

- 不改旧行。状态变了就追加新行，在“结论”里写“更正 C3：…”；撤回也是追加一行并写原因。`rk check` 对照 git 历史核查：提交过的行被改动或删除就报错。
- “已证实”“已否定”必须有证据：`run:<运行ID>`、`results/<文件>`、`doi:`、`arXiv:`、链接或仓库内的文件路径，多条用分号隔开。`rk check` 会核对证据是否存在。
- 作为证据的运行（`run:<运行ID>` 或 `results/<运行ID>.md`）必须正常结束，并且 `audits/` 里最近一次审计的总评是“可采信”。失败或没结束的运行既不能证实，也不能否定。
- 宣布“死路”要有一条被否定的精确陈述。一次失败的尝试只说明那个做法不行：记“未决”，注明“搁置，未否定”。
- 探索性发现记“未决”，“性质”写“探索”；经一次预登记的确认之后才能升为“已证实”。
- 机制性结论写明来自哪个模型 / 数据 / 条件；在第二个独立条件上复现之前，不据此设计方法。
