# 变更记录

## 0.4.0

第二期：研究线可以在本机和服务器之间交接。同一条线同一时刻只由一台机器推进，换机器时状态不丢、不会两边各写一份。

- **研究线推进权**。`collab.py lease` 在协调主机上登记每条研究线的持有者、到期时间和只增不减的编号（取得、交接、接管、重新盖章都加一）。到期且带证据才能接管。时间只看协调主机的时钟。
- **按线拆分的状态**。新增 `rk line new / take / beat / release / status / config`。每条线的状态在 `state/<线>.md`，开头记着持有者、编号和接手时的提交，由 rk 盖章并提交；`STATE.md` 改为生成的总览。旧项目第一次 `rk line new` 时，手写的 `STATE.md` 整份并进第一条线。`rk wait` 顺手续租。
- **一键交接（命令版）**。新增 `rk handoff <线> --to <机器代号>` 和 `/research:handoff`：先一次列出所有前置问题（没提交、没推送、落后上游、没跑完的运行、协调主机或目标机器连不上、代号不符）及修复办法；通过后写交接摘要 `handoffs/…md`、盖章提交、推送、在协调主机上转移推进权，可选在目标机器上直接 `git pull` 并接手。中途失败原样重跑即可。
- **防双写**。新增 PreToolUse 钩子：本机没有推进权（或本机记录已到期）时，拦下对 `state/<线>.md` 的 Write、Edit。`rk check` 按提交历史核对：旧编号下的写入如果不在新持有者接手时的提交之前（失联的旧推进者被接管后还在写），或者旧编号覆盖了新编号，都报错；持有者核对后 `rk line take <线> --restamp` 重新盖章。
- `rk run --line <线>` 记下运行所属的线；`STATE.md` 也用 union 合并，过期时 `rk check` 提醒重新生成。接续、启动、停下、现状技能和统筹者手册改为按研究线工作；SessionStart 钩子在压缩后带上本机持有的线的状态。
- 测试从 291 项增加到 370 项，新增“本机 → 服务器 → 拉回本机”和“失联的旧推进者被接管后还在写”两组端到端测试；Python 3.9 下同样全部通过。

## 0.3.0

第一期：研究记录可以在几台机器之间合并。本机和服务器各自推进、各自记录，经 git 汇合时不冲突，`rk check` 照样成立。

- **运行 ID 带机器代号**。新格式 `YYYYMMDD-<代号>-rNN-简称`，用 `rk id <简称>` 生成下一个；两台机器各自从 r01 编号也不会撞。代号取环境变量 `RK_MACHINE_NAME`，否则从主机名推出（macOS 用 LocalHostName；主机名是 IP 或 localhost 时用本机标识的哈希）。新运行必须用新格式、且只能用本机代号；旧格式的记录照常识别。`rk check` 发现同一代号被几台机器用过时给警告。
- **预登记先后看提交因果**。`rk check` 改为核对预登记提交是运行所用提交的祖先（`git merge-base --is-ancestor`），不再比较提交时间和启动时间；两台机器时钟不准也不影响。运行所用的提交不在本仓库历史里时报错，提示先合并那台机器的提交。没有记录提交号的旧运行仍按时间核对。
- **只追加的文件用 union 合并**。研究目录模板新增 `.gitattributes`：`LEDGER.md`、`LOG.md`、`LESSONS.md` 和生成的 `RUNS.md` 设 `merge=union`，两边追加的行合并时都保留。`rk check` 发现 `RUNS.md` 与运行记录不一致时提醒 `rk status --write`。
- **审计改为结构化登记**。新增 `rk audit record --runs … --verdict … [--report …]`：写 `audits/<编号>.json`，报告复制进 `audits/` 并记哈希，登记后改动报告会被查出；报告开头两行与参数不一致时拒绝登记。重审的新记录自动取代同一运行上的旧记录，先后看取代关系、不看时钟；两台机器各自登记的并存审计按较严的总评算。新增 `rk audit show`；`rk status` 和 `RUNS.md` 多一列“审计”。没登记的旧 `audits/*.md` 仍按“运行”“总评”两行读。
- 协议、统筹者、执行者、审计员说明和模板随之更新；测试从 225 项增加到 291 项，新增一组“两台机器各跑一批、经汇合点合并后 `rk check` 通过”的端到端测试。

## 0.2.0

保证落到机器检查上；修掉几处会让保证失效的漏洞。

- **在等用户的登记会被清掉**。新增 UserPromptSubmit 钩子：用户回复后解除 `rk block`，并提醒统筹者答复没解决就重新登记。以前只有 `/research:resume` 会解除，同一会话里答复后 Stop 钩子就永远放行。
- **远程运行记录拉回本机**。新增 `rk pull <别名>:<远程研究目录> <运行ID…>`：只拉已结束的运行，连日志一起，只补缺失的文件，不覆盖本机记录，同 ID 不同运行时拒绝合并。`rk check` 对远程未结束的运行给警告。
- **审计结论存档并参与核验**。新增 `audits/`（模板在其中）：统筹者把审计员报告原样存进去。“已证实”“已否定”依赖的运行，最近一次审计的总评必须是“可采信”，否则 `rk check` 报错。结果页模板加“审计”一节。
- **账本只追加由机器核查**。`rk check` 对照 `LEDGER.md` 的 git 历史，提交过的行被改动或删除就报错。
- **失败的运行不能支撑“已否定”**。以前只拦“已证实”。经 `results/<运行ID>.md` 引用的运行同样核查。
- **Stop 钩子改用 additionalContext**。按设计给的提醒不再显示成钩子错误，防循环保护不变。
- **子代理重新锚定**。新增 SubagentStart 钩子，给 `research:executor`、`research:auditor`、`research:scout` 注入研究目录与协议位置；子代理自动压缩后，下一次续用时会再注入。
- **拦截读取密钥和口令文件**。PreToolUse 钩子新增：Read、Grep 这些文件，或在 Bash 里用 cat、head、grep、cp、`<` 重定向等读它们，一律拦下；`ssh -i`、`ssh-add`、`chmod`、`ls`、`--password-file` 这类只引用路径的用法放行，公钥不受限。
- **本机判断不再依赖主机名**。运行记录新增 `machine`（本机硬件标识的哈希）；主机名随网络变化时，本机的运行不会再被当成远程。旧记录仍按主机名判断。
- 插件目录纳入 git；清单加 `author`；测试从 130 项增加到 225 项（新增预登记时间先后、预登记内容被换、拉回、审计、只追加、钩子输出格式等）。
